# Smart Agriculture Gaza AI

مشروع جامعي للزراعة الذكية يجمع بين إنترنت الأشياء والذكاء الاصطناعي. يصنف النظام حالة التربة ويحدد قرار الري من قراءات ESP32، كما يستخدم نموذج رؤية حاسوبية من نوع YOLO لكشف المحاصيل والأعشاب وتحديد أماكنها داخل الصور.

## رابط المشروع

https://smart-agriculture-gaza-ai.onrender.com

قد يستغرق فتح الموقع لأول مرة حوالي دقيقة لأن السيرفر يعمل على الخطة المجانية من Render.

## فكرة المشروع

يستقبل النظام القراءات التالية:

* درجة الحرارة.
* الضغط.
* رطوبة التربة.

بعد ذلك يمرر القراءات إلى نموذج `MLPClassifier` لتصنيف حالة التربة إلى:

* Very Dry
* Dry
* Wet
* Very Wet

بناءً على التصنيف، يحدد النظام إذا كانت المضخة تحتاج إلى التشغيل أو الإيقاف.

يحتوي المشروع أيضاً على نموذج `YOLO11n` مدرب للتعرف على فئتين داخل صور الحقول:

* `crop`: المحصول.
* `weed`: العشبة.

يعرض الموقع مربعات حول الأجسام المكتشفة، ونسبة الثقة لكل كشف، وعدد المحاصيل والأعشاب في الصورة.

## طريقة عمل النظام

1. تُدخل القراءات من واجهة الويب أو ترسل من ESP32.
2. يستقبل سيرفر Flask القراءات.
3. يتم تجهيز القراءات باستخدام `StandardScaler`.
4. يعالج نموذج التعلم الآلي البيانات.
5. يرجع السيرفر حالة التربة وقرار المضخة.
6. يعرض القرار في الموقع أو يرسله إلى ESP32.

بالنسبة إلى تحليل الصور:

1. يرفع المستخدم صورة للحقل من واجهة الموقع.
2. يجهز السيرفر الصورة بالحجم `512 × 512`.
3. يشغل النموذج بصيغة ONNX على الصورة.
4. يعيد النموذج مواقع المحاصيل والأعشاب ونسب الثقة.
5. ترسم الواجهة المربعات على الصورة وتعرض عدد النتائج.

## الملفات الرئيسية

* `app.py`: سيرفر Flask واستقبال الطلبات وتشغيل النموذج.
* `train_model.py`: تنظيف البيانات وتدريب النموذج.
* `data.csv`: بيانات التدريب الأصلية.
* `index.html`: واجهة الموقع.
* `esp32_node.ino`: كود ESP32 وإرسال القراءات إلى السيرفر.
* `real_data_nn_model.pkl`: النموذج المدرب.
* `real_data_scaler.pkl`: مقياس البيانات المستخدم مع النموذج.
* `weed_detector.py`: تجهيز الصور وتشغيل نموذج كشف المحاصيل والأعشاب.
* `weed_detector.onnx`: نموذج YOLO المستخدم في الموقع.
* `train_weed_yolo_colab.ipynb`: خطوات تجهيز بيانات الصور وتدريب النموذج وتقييمه وتصديره.
* `training_results`: نتائج التدريب والرسوم ومصفوفة الالتباس.
* `requirements.txt`: مكتبات Python المطلوبة.
* `render.yaml`: إعدادات نشر المشروع على Render.
* `run_local.bat`: تشغيل المشروع محلياً على Windows.

## تشغيل المشروع على Windows

1. ثبّت Python.
2. نزّل ملفات المشروع.
3. شغّل ملف `run_local.bat`.
4. انتظر حتى يتم تثبيت المكتبات وتشغيل السيرفر.
5. افتح الرابط التالي:

```text
http://127.0.0.1:5000
```

يجب إبقاء نافذة الأوامر مفتوحة أثناء تشغيل المشروع محلياً.

## التشغيل اليدوي

```bash
python -m pip install -r requirements.txt
python train_model.py
python app.py
```

* استقبال قراءات ESP32: `/api/esp32`

## ربط ESP32

يحتوي ملف `esp32_node.ino` على رابط سيرفر Render. قبل رفع الكود إلى اللوحة يجب كتابة اسم شبكة Wi-Fi وكلمة المرور محلياً داخل Arduino IDE.

لا يجب رفع كلمة مرور الشبكة إلى مستودع GitHub العام.

يقرأ الكود رطوبة التربة من مدخل ADC ويرسلها إلى السيرفر. قيم الحرارة والضغط الموجودة حالياً هي قيم تجريبية، ويمكن استبدالها بقراءات الحساسات عند توصيلها.

## ملاحظة عن البيانات

يقوم `train_model.py` بتنظيف البيانات وإزالة القراءات غير المنطقية قبل التدريب. لا تُستخدم أعمدة `status` أو `note` كمدخلات للنموذج، لتجنب إعطاء نتيجة التصنيف للنموذج أثناء التدريب.

## تدريب نموذج الصور

تم تدريب `YOLO11n` باستخدام Transfer Learning على 1,300 صورة بحجم `512 × 512` تحتوي على 1,212 صندوقاً للمحاصيل و860 صندوقاً للأعشاب. قُسمت الصور بنسبة 70% للتدريب و20% للتحقق و10% للاختبار، واستمر التدريب 30 Epoch على Google Colab باستخدام T4 GPU.

نتيجة النموذج في نهاية التدريب على مجموعة التحقق:

* Precision: حوالي 88.0%.
* Recall: حوالي 83.2%.
* mAP50: حوالي 92.5%.
* mAP50-95: حوالي 64.6%.

تم تصدير النموذج إلى ONNX مع Non-Maximum Suppression مدمج لتقليل مكتبات النشر واستهلاك الذاكرة على Render.
